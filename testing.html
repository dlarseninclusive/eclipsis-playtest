Watching the game while you play it

‹ Back to downloads · Release notes ›

How to watch the game while you play it — the journal, the F12 mark, the launch flags, and what a good report carries.

This page is for whoever is driving a build — playing it live, or running it for someone else, while a tester session (or a teammate) works out what happened. It covers the tools you have as an observer: the journal, the F12 mark, the launch flags, the dev console and the save files. It does not cover the check suites — those are for developers.

1. What a build tells you about itself

Every build prints and draws a version string: the release tag and the commit it was cut from, joined with · — for example:

playtest-14f31 · 53d7b7e

A development run (no release stamp) prints dev instead. You’ll see the string in three places, all reading the same value:

  • The title screen, bottom-left corner.
  • The in-game HUD, drawn small in the corner.
  • godot.log, the first few lines: [ECLIPSIS] version playtest-14f31 · 53d7b7e.

Quote it in every report. It is the one fact that tells a developer which commit’s code you were actually running — the tag alone is not enough once two builds share a tag during a fix cycle, and the commit alone means nothing to a release page.

2. The journal

The journal is a machine-readable log of what happened in a session, separate from godot.log (which is prose for a person standing at the machine). One JSON object per line, in user://logs/journal.jsonl, meant for a reader who is not in the room.

Where it lives

OSPath
Windows%APPDATA%\Eclipsis\logs\journal.jsonl
macOS~/Library/Application Support/Eclipsis/logs/journal.jsonl
Linux$XDG_DATA_HOME/Eclipsis/logs/journal.jsonl (usually ~/.local/share/Eclipsis/logs/journal.jsonl)

journal.jsonl is a fixed path a tailing reader can watch live — a second open file handle, not a periodic copy. Each session also writes its own dated copy, journal_<session-id>.jsonl (session id YYYYMMDD-HHMMSS); the game keeps the last ten and prunes older ones at launch. Want “the log from Tuesday” specifically, not just “the log from just now”? That’s the dated file.

Every line is flushed as it’s written, on both handles — a run that crashes still leaves everything up to that instant on disk.

The eleven fields

Every line — including a mark line — carries exactly these fields, in this order:

FieldMeaning
tWall-clock timestamp, local time, YYYY-MM-DDTHH:MM:SS.mmm.
rtSeconds since the process started (run time), to the millisecond.
dayThe in-world day number (0 and "paused" speed outside play — title, menus).
hourThe in-world clock hour, 0–24.
speedThe game-speed ladder’s own number (1/2/4), or "paused".
vThe build’s version string (see §1).
kindOne of the closed set of kinds — see below.
evThe specific event within that kind ("move_issued", "bark", "dawn"…).
whoThe body the line is about, when there is one — often empty.
textA free-text line, when the event has one (a note, a karma reason).
dataEverything else, flattened to JSON-safe values — see below.

data is flat: a position becomes [x, y], an NPC becomes its name, and a nested dictionary is stringified rather than left as a tree to recurse into — the one declared exception is data.hud on a mark line, which stays a real object. The file is seven-bit ASCII on disk — anything above 0x7F (this game’s prose is full of em-dashes) is escaped to \uXXXX, so nothing comes back as mojibake through a terminal with a different code page.

The kinds

The closed set, enforced at runtime — a caller that hands in anything else gets a developer error and a warn line in the journal itself, so the reader also learns a line was dropped rather than silently missing it:

KindMeaning
sessionProcess/run lifecycle: start, phase, world (the seed/scenario/save once play begins), quit.
inputOne line per bound-key action — every keybind, discrete verbs only, no mouse motion/held keys/frames.
orderThe player’s standing click-order: issued/cleared, for move and attack.
stanceThe squad’s stance (hold/follow/aggressive, etc.).
driveWhich body you’re driving — you, or a companion you’ve taken the reins of.
recruitA recruit attempt and, on refusal, the machine-readable reason id.
noteEvery line the player is shown in the note log.
chronicleWorld history off the event bus that isn’t one of the named families below.
simWorld-level edges: raids, famines, caravans, weather, the eclipse, dawn.
custodyBeing captured, held, ransomed, released — and what happens around it.
ledgerCoin: levies, wages, taxes, bounties, trades, karma writes.
needsThe deprivation ladder (thirst/hunger rungs) and passing out / coming round.
saveA save was written — manual (F7) or autosave, told apart by path.
warnSomething non-fatal the journal itself wants the reader to know about.
errorDeclared kind; no call site writes it in this build (see §9).
perfFrame-time health — slow-frame buckets and a one-minute summary.
markAn F12 bug mark — see §3.
combatOne line per resolved exchange (hit/blocked/dodged/crit/disarm/limb/wound/kill/assassinate).
alertA standing condition’s edges (raise/clear) — e.g. starving, wanted.
llmLocal-LLM dialogue/decision routing and fallbacks.
audioThe adaptive music director: state, cue, stinger.
speechUnprompted NPC speech: bark, chain, chain_cut, enrich.
arcA private NPC arc’s stage changes (assigned, stage).

A worked row

An F12 mark, trimmed (a real one also carries squad and nearby):

{"t":"2026-09-17T14:12:05.331","rt":581.31,"day":2,"hour":9.6,"speed":2,"v":"playtest-14f31 · 53d7b7e","kind":"mark","ev":"bug","who":"","text":"","data":{"n":1,"frame":"20260917-140203_1_day2_09.60.png","recent":["move_issued","dawn","rung","bark"],"driving":"player","pos":[4321.0,8765.2,0],"camera":[4321.0,8765.2],"zoom":1.0,"interior":"playing","hud":{"thirst":62.0,"food":48.5,"hp":100.0,"coronas":340,"stamp":"playtest-14f31 · 53d7b7e"}}}

3. F12 — the mark

Press F12 the moment something looks wrong — not after you’ve reacted to it, not after you’ve closed the panel that showed it. F12 is read ahead of everything else that handles input, so it works on every screen and nothing in the game can eat the key first.

One press writes, in order:

  • A mark/bug journal line — written first, and it carries the exact PNG file name in data.frame, plus data.recent: the ev ids of the last twenty journal lines before this one, so the mark carries its own immediate history.
  • A screenshot, saved beside the journal’s own logs at user://logs/marks/<session-id>_<mark-number>_day<D>_<HH.MM>.png.
  • A toast in the note log confirming it: Marked bug #N — frame saved.

A report built from one mark’s line and its PNG is self-contained — nothing else needs to be attached.

4. Launch flags

--journal-echo mirrors every journal line to the log as it’s written, in addition to the file. What that means depends on what’s attached to stdout:

  • A shipped build has no console. The exporter refuses to ship the console-wrapper exe. But Godot’s file logger mirrors every print into godot.log regardless, so with --journal-echo the mirrored lines land in user://logs/godot.log, interleaved with the game’s ordinary log prose — not in a visible window.
  • A dev build run from a terminal shows the echoed lines live, as you’d expect.

Launch it, on each OS:

# Windows — from an existing terminal, or as a shortcut target
cmd /c eclipsis.exe -- --journal-echo

# macOS
"/path/to/Eclipsis.app/Contents/MacOS/Eclipsis- The Shattered Expanse" -- --journal-echo

# Linux
./eclipsis.x86_64 -- --journal-echo

The -- matters: Godot claims everything before it for the engine itself and would refuse an unknown flag; everything after it reaches the game.

Every other flag the game reads at launch:

FlagWhat it does
--journal-echoMirrors every journal line to the log (see above).
--seed <n>Arms the seed the next new world is built from (hex or decimal). Does not affect a loaded save.
--screenshot <path>Renders, saves one PNG to <path>, and quits — for driving the game somewhere with no screen-recording permission.
--screenshot-after <n>Frames to wait before that screenshot (default 120, ~2s at 60fps) — lets the title fade and the world generate first.
--cinematicStarts with the HUD hidden — same as pressing F10 or typing hud off at the console, but from launch.

--scenario is not a flag the shipped game reads — it only exists as an argument to one dev probe tool. To apply a start scenario to a running game, use the console’s scenario <id> (§6).

5. Reading the file

Three copy-paste filters. Substitute your own journal path (§2).

PowerShell — list rows of one kind (e.g. every alert):

Get-Content "$env:APPDATA\Eclipsis\logs\journal.jsonl" |
  ForEach-Object { $_ | ConvertFrom-Json } |
  Where-Object { $_.kind -eq 'alert' }

Python — the same, one kind at a time:

python -c "import json,sys
kind = sys.argv[2]
for line in open(sys.argv[1]):
    d = json.loads(line)
    if d.get('kind') == kind:
        print(line.rstrip())
" "$APPDATA/Eclipsis/logs/journal.jsonl" alert

grep — every line mentioning a body by name (works because who, and most data values, are plain strings — no JSON parsing needed for a quick look):

grep '"Merrow"' "$APPDATA/Eclipsis/logs/journal.jsonl"

Lining a mark up with what led to it. A mark’s own line already carries data.recent — the ev ids of the twenty lines just before it — so you often don’t need the file at all. To see the actual lines (not just their names), find the mark by its frame name (which is unique) and take the handful of lines before it:

$lines = Get-Content "$env:APPDATA\Eclipsis\logs\journal.jsonl"
$i = ($lines | Select-String -SimpleMatch '"frame":"20260917-140203_1_day2_09.60.png"').LineNumber
$lines[($i-21)..($i-1)]

6. The dev console

Open it with the backtick key (`, remappable). The world pauses while it is up. Enter runs the line and leaves the answer on the console; backtick, Esc, or Enter on an empty line closes it. Every command lists what it accepts with <cmd> ?, and Tab completes.

The five verbs a tester reaches for most, for reproducing and narrating a run:

VerbUse
tp <city> / tp <x> <y>Jump straight to where something is happening, instead of walking there.
seed <n>Arm the seed the next New Game builds from, so a bug tied to a world can be handed back exactly.
time <hour>Set the clock, to reach a day/night state on demand.
musicReports the adaptive score’s actual state (cue, stems, mute) — the one system whose state is otherwise inaudible as a fact.
voicesReports the last NPC line spoken and why it was (or wasn’t) heard — same idea, for speech.

7. Saves and profiles

Where saves live. Same user:// root as the journal (§2): <data path>/Eclipsis/eclipsis_*.json. The files:

FileWhat
eclipsis_save.jsonThe F7/F8 quick-save slot.
eclipsis_autosave.jsonWritten each dawn, and on quit.
eclipsis_slot_1.json … eclipsis_slot_3.jsonThe three named slots from the save/load screen.
eclipsis_soak_save.jsonOnly present if a headless soak test aged a world into it — not something normal play writes.

Autosave cadence: at every in-world dawn, and once more on quit.

Driving a build by hand for testing is not running the check suites — the suites sandbox their own data folder and restore your real profile byte-for-byte; you, playing normally, are on the real profile, same as any player.

Loading an older playtest save is supported, but only forward from whichever builds the current release’s notes say carry forward — each release on the playtest repo states this explicitly, e.g. this build’s notes read “Your 14f27 through 14f30 saves load. Nothing here touches the world’s dice.” Check the notes for the build you’re on rather than assuming an arbitrary old save will open.

8. Reporting

Every report should carry:

  • The version string (§1) — quoted exactly, from the title screen, HUD or godot.log.
  • The seed — off the session/world journal line (data.seed), or from what you typed at seed <n> if you armed one yourself.
  • What you did — the order/input rows in the journal in the run-up to the problem (or just data.recent off the mark itself, §2–3).
  • The mark’s PNG — press F12 at the moment, attach the file it names.
  • The journal file itself — the dated journal_<session-id>.jsonl, or the fixed journal.jsonl if that’s what you were tailing.

Where to file: Issues on the playtest repo. A plain paragraph with the five items above is the whole shape — nothing more is expected.

9. What is not there yet

  • No viewer. The journal is a flat JSONL file and nothing more — there is no in-game or standalone tool that renders it as a timeline. The file is the tool; read it with the filters in §5.
  • No NPC decision rows for named bodies, yet in earlier builds — a body’s utility-AI choice (flee / seek / avoid / hunt) wasn’t journalled independent of what it did on screen. This build, 14f31, is the one that adds it: named bodies now write a row each time they pick a goal.
  • error is a declared kind with no call site currently writing it — reserved, but nothing in the codebase logs under it today.
  • No way to filter the journal in-engine. --journal-echo mirrors everything; there’s no launch flag or console verb to echo only one kind.
