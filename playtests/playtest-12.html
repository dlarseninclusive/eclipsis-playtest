What was actually proven

Three tiers, because they are not the same claim. An exported build ignores the test hooks, so some things can only be checked against source — and saying so is the difference between a gate that means something and a gate that means whatever the last person had time for.

Verified on the shipped build the artifact itself, launched and inspected
  • Save migration, four checks. A fresh upgrade copies all four files with matching MD5s. The old folder survives byte-identical — copied, not moved. A second launch does not copy again. And a marker recording a successful migration never re-runs, which was the failure worth fearing: this bug hid saves, the other would have eaten them.
  • The broken state heals. Tested against the folder the first cut actually produced, not a reconstruction of it: skipped → copied, bytes intact.
  • Window title reads “Eclipsis: The Shattered Expanse”, read off the running process. Not “Godot Spike” any more.
  • The update notice cannot be tested yet — it shipped in this build, so the older one has no code to display it. Validates at Playtest 13.
Verified against source at the ship hash 3c8f272 — not the export
  • Road travel, both states, same world. On: the route joins the road and stays on it 53% of the walk. Off: 8%, the old direct line. Two distinct, correct behaviours.
  • Ctrl labels in fog — the worst case — now crisp on a dark backing where they were grey on grey.
  • MEDS · H is on the quick bar, and ROAD ON shows the travel mode.
  • Faction starts pass 13 of 13 on scenario mechanics: factions valid, kit replaced, reputation and bounty seeded.
Not tested this cycle named, rather than left as silence
  • Following someone through a town — roofs, gates, floors. The automated runs stage clear of towns by design, so this case has been exercised by nobody. It is the likeliest thing in the follow order to break.
  • Rebind screen, run lock latch, sprint on a long straight. Keyboard-in-hand items.
  • The update notice, for the reason above.

The walk

Reported as: “I am on a long walk south, and zigzagging, this walk is taking a lot longer than it needs to.”

It was not the roads. The road preference had never engaged in play — the flag that protects a road route was raised and then wiped fifteen lines later, on every single order, by a progress gauge that shipped in the same slab. The code's own comment described the exact failure it was failing to prevent.

Below: 209 long hauls on the repaired build, random worlds, one machine to itself. Efficiency is distance walked over distance made good — 1.00 is a straight line.

Before the repair the same measure ran 1.52 – 1.59. Not one of the 116 arrivals exceeded the detour limit the game promises itself. And the wandering loop we killed a fortnight ago has stayed dead: 181 of 209 hauls gave ground zero times, 28 gave it once, none twice.

What is left is a different question and a quieter one: the walks that don't finish are not walking badly, they are just not finishing. That points at pace or interruption rather than routing. Nobody has ever reported it as a feeling, so it waits.

One finding

Not a blocker · silent

Four of nineteen faction starts don't take you home

Pick the Veiled Blades, the Hollowed, the Eclipse Choir or the Quiet Mile and you begin at the generic world spawn instead of with the people you chose. Every faction that holds territory lands correctly and far apart; these four cluster on the same default point.

# start_scenario.gd:61 var terr := ...get("territory", []) if not terr.is_empty(): p.set_center(...) # ← empty territory: placement silently skipped

Three of the four have a home in the data — Reedshadow Village, the Processing Yard, the Totality Camp — and you simply don't arrive there. The Quiet Mile has no city at all and starting on the road is correct for it.

These are the same four rows whose empty territory broke a suite check that sat red for twenty days. One data gap, second symptom. The fix is to fall back to the faction's city before falling back to nowhere — and to say so in the log, because the silence is half the defect.

What this build does not fix

The world's traffic is unchanged

“I never get the feeling the simulation is running without me.” That was traced: the caravan population is capped at one, world-wide, and the cap turned out to be an accident — inherited from the old Python build and never given a number, while every other travelling party got one (wayfarers 12, patrols 7, chain gangs 2).

The dial now exists. It ships at its default of 1, so this build will feel exactly as empty as the last one. The number is set to 4 in the next build, behind a frame-time check. Expect no change here; expect it there.

The one that nearly shipped

The first cut of this build was pulled. Its save migration never ran — not sometimes, never. It asked whether the new folder already held player data, and the engine's own shader_cache and vulkan directories, created at startup a moment before the question was asked, answered yes. Every upgrading player would have launched into an empty save menu — with their game safe on disk, invisible, and a marker ensuring it never tried again.

Nine hundred and six automated checks passed on that build. They could not see it, because they staged their own folders where no engine had ever run. Anything that depends on engine startup order is invisible to a check that builds its own fixture — which is the second time this cycle the shipped artifact held something no source-side test could reach.
